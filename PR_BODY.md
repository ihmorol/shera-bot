## #83 disposition (S27-GAP-1 — the setsid grandchild survived the group kill)

- **Red-first**: the ST-04 detached leg committed RED on the unfixed tree — the session-escaped grandchild alive past the typed cancellation, reproduced in-suite (`tests/security-evidence/2026-11-10-gap1-setsid-red.txt`). The pre-existing group-kill leg stayed green (nothing weakened, G5).
- **LANDED (runtime cancellation code, live-verified on this host)**: `apps/user-runtime/src/adapters/process/escape-sweep.ts` + the `killTree` wiring — at cancel(), the wall clock, and the post-exit reap: the PPid chain walked BEFORE the group kill while intact; /proc swept for processes NEW in the execution's window (spawn-time pid→starttime snapshot; the starttime compare is the pidfd-reuse-safety stand-in — Node exposes no pidfd surface, a native FFI dependency rejected per E15), their OWN session leader (sid === pid — the only shape setsid(2) produces), INSIDE the execution's own user namespace (the leader's PRIVATE uid_map — the D27 envelope; the host-map case disables the sweep: a control that cannot scope itself does not run); verified kills (starttime re-checked — pid reuse spared). The uid_map read is lazy + cached (probed live: at spawn-return the fork is pre-exec and carries the host map). Green: ST-04 2/2 (`…-gap1-setsid-green.txt`); the neighbor suites 60/60.
- **Design hazard closed before any run**: a naive session-leader sweep could kill vitest workers / sibling suites (they spawn detached = session leaders); the uid_map condition excludes everything outside the execution's namespace by construction.
- **Waits for the deployment host (runbook §9, Manual decision 6)**: PID-namespace containment at spawn closes the residual — a double-fork orphan completing inside one sweep window without setsid, an escapee nesting its own userns, a leader without a private map (sweep disabled — honest degradation). Recorded in SECURITY-GAPS §GAP-1 (the finding's history kept, the disposition appended), THREAT-COVERAGE (ST-04 AUTOMATED both legs), and the runbook.

## #84 disposition (S27-GAP-2 — the cgroup memory layer "dead on the recorded host")

- **The re-verification changed the picture — recorded, not absorbed (G5)**: the delegated subtree is LIVE on this host now (systemd `user@1000.service` `Delegate=yes`; a direct leaf with a writable memory.max created outside any code under test; kernel 7.0.0-42 moved since the S27-era observation). The S27-era "not writable" no longer reproduces.
- **Two real masking defects, fixed red-first** (`tests/security-evidence/2026-11-10-gap2-cgroup-{red,green}.txt`): (1) `probeCgroupBaseDir`'s cleanup (`rmSync(probe, { force: true })` on a directory) threw EISDIR on every delegated host and returned null — a live layer invisible behind its own cleanup failure; the committed ground-truth test pins the mask (RED), the verdict is now the mkdir with best-effort rmdir(2) cleanup (cgroupfs pseudo-files are not unlinkable); (2) `teardownCgroupLeaf`'s same shape could never remove a cgroupfs leaf — fixed identically.
- **A third, live finding: memory.max alone is not a HARD boundary** — a 512 MiB tmpfs hog wrote straight through a live memory.max via swap reclaim (observed: DD-RC=0, `memory.events` max unmoved). `applyCgroupLayer` now writes `memory.swap.max = 0` beside memory.max — the S06 container posture (MemorySwap = Memory) applied to the execution leaf.
- **The committed answer to GAP-2's exact question** (the new ST-05 leg): a tmpfs hog invisible to RLIMIT_DATA (dd into /dev/shm) waits until it observes itself inside its execution leaf, then EXECs dd (the hog becomes the leader) — the kernel SIGKILLs it at memory.max=256 MiB and the exit is the TYPED `memory_oom`. Refused-by-limit vs refused-by-allocator: distinguished. The honest-degradation branch stays for non-delegated hosts.
- **Waits for the deployment host**: the VM's own verdict — `infra/deploy/verify-cgroup.sh` (verifies the FULL delegation sequence; mkdir-only lies — recorded in the script) + the ST-05 re-run on the VM; the pre-move window residual (a charger that begins before the D27 leaf move lands — the Compose container-level cgroup covers it); the runbook §8 procedure.
