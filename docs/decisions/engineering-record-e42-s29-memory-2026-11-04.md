## Decision and rationale

**The boundary is structural: an Agent-private memory's Operation-context visibility is a COLUMN on the row, set only by the user's explicit decision.** Migration v21 adds five STRICT tables — `memory_entry` (the D37 scope CHECK set `account|workspace|operation|task|agent_private`; the owner/operation/task binding columns the visibility table reads; sensitivity `normal|sensitive`; the publication columns `published`/`published_into_operation_id`/`published_at`; the provenance pair `source_refs` JSON + `confidence`; `origin user|automatic` and `created_by`; `expires_at`; `forgotten_at` unused — the forget is a real DELETE, not a soft flag), `memory_version` (append-only history — version 1 is the creation, every edit/restore appends; the repository has no UPDATE statement for history rows), `memory_publication_request` (the S9 queue: `pending → approved | dismissed`, with who requested and who decided), and the two auto-memory control tables (`memory_settings` global + `memory_agent_settings` per Agent). No FOREIGN KEY is declared (the v4 discipline); every table is workspace-scoped (E12). AC27 holds BY CONSTRUCTION: `agentContext()` — the ONE context-assembly projection — can only return another Agent's private row through `published === 1 AND published_into_operation_id === <the operation being read> AND the viewer participates in it`; publication shares into ONE Operation and never opens the private scope (the owner's own context keeps the entry, and the cross-Agent detail read stays 403 after publication). The D37 visibility TABLE is enforced in `visibleEntries()`: account memory NEVER reaches an Agent (the user and explicitly authorized services only); operation memory reaches participating Agents; workspace memory reaches workspace Agents (the recorded prototype default policy — the per-Agent allowlist is the recorded seam, named in NOT verified); task memory rides the same Operation linkage.

**Publication is an explicit USER action with an approval trail (G6, AC2).** `memory.publish_decision` refuses an agent actor with the typed 403 `MEMORY_COMMAND_ACTOR_FORBIDDEN`; a SENSITIVE entry additionally requires a PENDING publication request before any approve (the typed `MEMORY_PUBLICATION_APPROVAL_REQUIRED`) — the decision row records `requested_by` and `decided_by` with timestamps, and dismiss withdraws an active publication or dismisses a pending request. Automatic learning rides the typed contracts event: `memory.candidate_proposed` (D37's payload verbatim — memory_id, scope, summary, source_refs, confidence, sensitivity, expires_at; the envelope's actor IS the proposing Agent) is journaled by `proposeCandidate` AFTER the gates pass — the proposal is an event, never an agent-side write (G2), and the event can never carry a secret because the scan precedes the journal.

**The write-time secret rejection is three layers over the recorded vocabulary (AC2, D22/E9, G3), and the embed decision was made from the code.** secretlint (`@secretlint/core` 13.1.0 + `@secretlint/secretlint-rule-preset-recommend` 13.1.0, both MIT — licenses verified in the E-note below; install footprint probed at ~1.5 MB across four packages with the rules bundled, `engines.node >= 22` satisfied) is EMBEDDED and invoked programmatically through `lintSource` with `maskSecrets: true` so no rule message carries matched text back; the preset's rules see memory writes through the `text` content type, and the AWS rule's opt-in `enableIDScanRule` is ENABLED for memory (an un-keyed AWS access-key id must still be refused on exactly this surface). The probe proved the embed contributes rather than decorates: the bare `ghp_…` GitHub-token fixture is caught ONLY by the preset's GitHub rule. Layer two is the recorded S18/S25 redaction vocabulary re-expressed as DETECTORS (the key-assignment sweep including the CSV-doubled-quote alternative, PEM blocks, bearer tokens, Authorization headers, connection-string userinfo — the same families the terminal boundary collapses, the memory boundary refuses; attribution in the module header). Layer three is the entropy pass (≥ 32 chars, mixed classes, Shannon ≥ 4.2 bits/char — hex digests cap at 4 and never trip). The scanner failing is a fault, not an allow: a scanner exception rejects the write (`scanner-unavailable`). A rejection means NO row, NO version, NO event, NO receipt — and the response names the RULE classes only (`internal_details.rules`), never the matched content. The never-stored guarantee is pinned by the whole-database byte scan (db + WAL + shm sidecars — the S23 custody-scan posture) over the full fixture table; the scan covers edits too (an edit is as much a write as a create).

**Provenance is never optional (AC3).** Zero source refs is the typed `MEMORY_PROVENANCE_REQUIRED` for user writes AND automatic candidates — checked BEFORE the scan, before anything exists. Every entry exposes `origin`, `created_by`, `source_refs`, and `confidence` on every read; the S9 surface renders the "Remembered from …" line (or "Added from …" for user writes) with the confidence figure and the actor.

**The user controls are the issue's list, each pinned (AC4–AC8).** Version restore: edit then restore returns the previous content and the history is PRESERVED (created, edited, restored — the restore APPENDS; the discarded version's row keeps its own content, pinned at the storage layer). Auto-memory: the global switch and the per-Agent switch each stop new automatic writes at the TOP of `proposeCandidate` (before provenance, before the scan, before anything exists) with the typed `MEMORY_AUTOMATIC_DISABLED`; explicit user writes never consult the switches. Permanent forget: the entry, its version rows, and its publication requests are DELETED — nothing restorable survives, the forget confirmation copy names the version count and says "This cannot be undone — there is no restorable copy afterwards" (the recorded mockup-defect class of contradictory "permanently forget — restorable" copy is impossible here), the honest `forgetPreview` counts what a forget would remove, and a second forget is the typed 404. The cross-Agent denial sweep (AC7) pins the FOUR read shapes — both context reads (with and without the operation binding), the direct detail read (the typed 403 `AGENT_MEMORY_ACCESS_DENIED`, the S11 private-folder analogue), the Operation-context projection, and the spoofed retargeting query (the strict query schema refuses the unknown parameter outright — a retargeting query is a 400, not a read). Pack upgrades never rewrite memory rows (AC8): the branch re-composes the runtime over the same database (pack re-load, workspace re-pin, Agent re-seed — the full upgrade path) and pins the memory row byte-identical (summary, content, confidence, timestamps unchanged).

**The S9 Memory surface (AC9) renders the runtime's OWN record.** The browser trust boundary grows by exactly two routes: `GET /v1/memory` (the management read) and `POST /v1/memory/commands` (the ONE typed commands envelope); the Agent context/detail reads are deliberately OFF the browser allowlist (runtime-internal acting-Agent reads, the S11 folder-route posture), and every command's acting user is bound SERVER-SIDE by the proxy's session binding (`SESSION_ACTOR_BINDINGS` gains `/v1/memory/commands → actor` — the browser client names the actor shape only; the audit trail is the session identity). The surface: the per-scope breakdown (all five D37 scopes as groups with their runtime counts, private and shared in their own groups), the publication queue (empty state teaches the boundary; pending rows render entry, proposer, and both decisions), the "remembered from …" provenance lines with confidence and actor, version history with restore buttons (history opens itself once a memory has more than its creation version), the honest two-step permanent forget, publication controls shown ONLY where publication applies (private or sensitive entries — showing them on shared non-sensitive entries would dilute the boundary they gate), and the auto-memory toggles (global + per-Agent) with copy that says exactly what turning them off stops. A refused write shows its typed refusal where the action happened (`data-testid="memory-rejection"`; the secret refusal's copy is authored for display: "Not saved — this looks like a credential or secret. Secrets are never stored in memory."), never an input that pretends to work. Edits preserve provenance (an edit re-sends the entry's own source refs — an edit never rewrites where a memory came from). The settings overview links Memory as live; it is removed from the pending roster (the E39 F3 rule).

## Alternatives considered (preserved)

- **A scoped rule-subset port of secretlint** (the issue's recorded fallback): rejected — the embed decision was made from the code: the footprint probed light (~1.5 MB, four packages, rules bundled), the license MIT, and the programmatic `lintSource` API clean; a port would have re-implemented the AWS/GitHub/connection-string rules poorly. The recorded fallback stays recorded; the probe evidence lives in the record.
- **Reusing the terminals' `redactSecrets` directly as the detector:** rejected — that module REDACTS (replaces with `[REDACTED]`), the memory boundary must REJECT (nothing stored); the vocabulary is shared but the regexes are re-expressed as detectors with the attribution recorded, and the scanner adds the entropy pass and the secretlint layer the terminal boundary does not need.
- **A soft-delete `forgotten_at` flag for the permanent forget:** rejected — "permanently" is the user's word; a soft-deleted row leaves restorable bytes in the database file, and the honest copy would contradict itself. The forget is a real DELETE of entry + versions + requests.
- **Publication as a boolean flag without the request row:** rejected — the S9 queue (approve/dismiss) and the sensitive-approval trail need the recorded request with who requested and who decided; a bare flag carries no approval evidence (G6).
- **Per-scope entry reads as separate routes (`/v1/memory/:scope`):** rejected — the management read returns the full per-scope breakdown in one workspace-scoped GET; more routes would grow the browser allowlist surface without adding capability, and the per-scope grouping is a rendering concern.
- **A create form on the S9 surface:** rejected — the UI_DESIGN S9 row names view/edit/delete/forget/toggles/provenance/restore, not create; memories are created by Agents through the runtime (automatic) and the user's edits exercise the same rejection path. The recorded spec gap closed by this slice is the per-scope breakdown, the queue, provenance display, restore, and the toggles.
- **Making the memory service async only at the transport:** rejected — the secret scan (secretlint's `lintSource` is async) must guard EVERY caller including the runtime's own `proposeCandidate`; the service methods are async at the source so the boundary has no sync bypass.
