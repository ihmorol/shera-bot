## Machine reality (the issue's leverage note, corrected and recorded — never silently descoped)

The issue's open-source leverage note names `docker run/exec` sandboxing. **Docker does not exist on the building machine** (the socket is root-owned and the builder is not in the docker group), so the D27 envelope was built on the OS primitives that DO exist, PROBED before design on this box (Ubuntu 24.04, uid 1000): unprivileged user namespaces are allowed (`unshare --user --map-root-user --net` succeeds — while plain `unshare -n` without a user namespace is refused, as expected), util-linux prlimit is present, and a DELEGATED cgroup-v2 subtree exists under `user.slice/user-1000.slice/user@1000.service` (mkdir + pid-move + memory.max/pids.max writes all succeed). The probe results are pinned by the adapter's own suites, and every layer degrades HONESTLY (typed failures or recorded `null`) rather than asserting enforcement that is not there (G4). The compose deployment (S35) is where container-grade enforcement (`network: none`, a dedicated sandbox user, memory limits at the container boundary) lands — the contracts and the composition are shaped so S35 replaces none of this code.

## Decision and rationale

**The sandbox envelope is five kernel/OS layers, each probed, each verified, each honestly recorded.** (1) NETWORK DISABLED BY DEFAULT: the child execs inside `unshare --user --map-root-user --net` — the loopback device exists but is DOWN and the namespace has no routes, so a real outbound connect fails with ENETUNREACH (pinned by test, and the composed test compares `/proc/<pid>/net/route` — EMPTY for the sandbox — against `/proc/self/net/route` — populated for the runtime: the separation is DEMONSTRATED at the kernel level, and the runtime's own network surface answered the same test's HTTP calls, which is the research-tools posture S25/S35 build on). A missing unshare binary or a kernel refusal is a FAIL-CLOSED typed error — the execution never runs networked. (2) KERNEL RESOURCE LIMITS via prlimit(1) exec'd as a BINARY (no shell, the S16 pattern): `--data` (RLIMIT_DATA — chosen over RLIMIT_AS because interpreters reserve large VIRTUAL address space; probed: node v24 boots at data ≥ 1 GiB but not below ~2 GiB of AS), `--cpu` with the soft:hard split (`N:N+1` — with soft==hard the kernel's SIGKILL-at-hard races SIGXCPU-at-soft and the typed signal loses; probed), `--nproc` (inside the user namespace the kernel counts the NAMESPACE's own processes — probed, and the gateway is untouched), `--fsize` (RLIMIT_FSIZE → SIGXFSZ). The applied ceilings are VERIFIED by reading `/proc/<pid>/limits` during the run (bounded non-blocking poll) and recorded in the result text (`limits verified: data=… cpu=… nproc=… fsize=…`) — D27's "tool-created processes inherit the parent task's limits" is demonstrated, not asserted. (3) CGROUP LAYER (best-effort, recorded): when the delegated subtree exists, the child is moved post-spawn into a per-execution leaf with memory.max (the kernel OOM-kills a real hog — the typed `memory_oom` death RLIMIT_DATA cannot produce) and pids.max (bounding the tree from OUTSIDE the namespace); a missing delegation leaves the layer honestly null and RLIMIT_DATA contains the hog by allocation refusal — both postures pinned. (4) WALL CLOCK: the tool's own timeout_ms drives a group SIGKILL. (5) PROCESS-TREE TERMINATION: the child runs detached (own process group); cancel() and the wall clock SIGKILL the whole group with the S19 post-exit reap — no descendant survives, asserted against the live process list with a per-run marker (a crashed worker's orphans can never satisfy a later run's assertion).

**The executor is the ONE path, extended by the seam E33 recorded — nothing beside it.** The bindings are TOOL BINDINGS in the S21 executor's registry: their sync `execute` is a typed refusal even with a genuine authority token (pinned — the process-backed effect is unreachable except through the dispatch), and the OPTIONAL `executeAsync` seam is the E33-recorded arrival: `executeProposal` answers `dispatched` (the row is `running`; the child runs OUTSIDE the caller's transaction), with a `completion` that settles the row (redacted, bounded, exit code and duration recorded) and a `cancel` handle wired to the executor-owned AbortController. The S20 semantics survive intact: the gated pause still writes ZERO rows pre-decision and the withheld execution still runs ONLY through `runWithheld` post-decision (AC7 pinned with a real child and a sentinel file); the grant fast-path consumes a one-time grant only when the completion settles as executed. The integration with main-with-S22 closes E35's recorded hook: `cancelForTask` now fires the in-flight dispatched executions' cancel seams (the child tree dies with the task — D27), and the settlement path refuses to rewrite a row the cancellation sweep already terminalized (G5: a recorded end stays recorded) — S22's suites and S26's both green through the merged executor.

**The D27 path discipline is a policy layer the bindings apply before every file operation.** The scope root resolves to its REAL location first (a symlinked root pins there); absolute host paths are refused outright; every existing path component is realpath-checked (planted-symlink escapes refused at execution time — the AC2 shapes); directory preparation walks segment by segment, checking each prefix BEFORE creating the next, so a planted directory symlink is refused before anything is created through it. The child environment is a FIXED allowlist (PATH/HOME=workdir/TMPDIR inside the workdir/LANG/TERM) — the runtime's `process.env` is structurally invisible (AC5's planted-secret pin, asserted at the adapter, the binding, and the history row). The code payload is written to a runtime-named 0600 file inside the checked workdir and unlinked after the exit; a dedicated sandbox uid via setuid is not available unprivileged — the child inherits the runtime's already-unprivileged uid and the user namespace maps it to root ONLY inside the namespace; S35's compose `user:` directive is the recorded final hardening.

**Output capture is redaction-first at one boundary before every sink (G3/AC6/AC8).** Chunks pass `redactSecrets` ONCE at the stream boundary; the same redacted text feeds the terminal recorder (whose own pass still runs — defense in depth), the bounded capture, and the artifact bytes, so the terminal rows, the journal payloads, the history row, and the artifact are clean by construction — pinned by a whole-database byte scan (the S18 pattern) plus artifact-bytes and terminal-record scans. Streams over 64 KiB become ARTIFACTS (S17's repository, producer task/agent recorded) with the result text carrying a bounded head plus the artifact pointer (the display prefix of the artifact id — the executor's high-entropy pass collapses full UUIDs as opaque tokens by design, and the durable linkage is producer_task_id plus the artifacts API); the adapter's forwarded-stream cap (4 MiB) and the capture cap bound the runtime's memory and the journal whatever the child emits, with honest truncation markers. Exit codes and durations are ALWAYS recorded; a limit death is the typed `SANDBOX_LIMIT_EXCEEDED`; a cancellation is `TOOL_EXECUTION_CANCELLED`.

**The S18 redaction boundary gained a performance fix with pinned semantics (recorded, not silent).** Feeding real process output through the S18 key-assignment sweep exposed a quadratic backtracking (the unbounded greedy key span retries at every position of a long non-secret token run: 8.7 s for ONE 64 KiB chunk — which would have frozen the gateway under large outputs). The sweep is now anchored to token starts (a negative lookbehind); semantics are unchanged (a full-token match dominates every mid-token start the unanchored span could find), the 12 S18 redaction tests pass unmodified, and the sweep is linear (8.7 s → 2 ms on the same chunk). S26's suites consume the same layer.

**Composition and surfacing.** The two tools register as platform built-ins (`tool_code_exec`, `tool_terminal_exec`) behind the composition's `executionTools` option (the workspace scopes are configuration — G4: without them the tools do not exist and the inventory answers truthfully); main.ts wires them for the real runtime with a container-local `data/execution-workspaces/<workspace_id>` scope created 0700. The UI work is the honest surfacing through the EXISTING surfaces (no new user-visible surface shipped, so the impeccable UI gate did not run): the D35 tool cards and the Tool history tab show command/workdir/resource policy/approval state from the executor's records (the bindings' `preview` is the command-kind preview the ladder prescribes), and the S18 terminal panel goes ALIVE — real executions stream through `TerminalRecorder` on `RuntimeHandle.terminals` (started: command, workdir, the ACTUALLY enforced resource policy, the record-time approval state `approved` for grant/decision-backed runs; output chunks; exit) — the E31 D14 deferral fulfilled, pinned by the composed test reading the terminal events API. No execution route exists in the browser allowlist (unchanged from S21): tools execute only through the runtime executor.

## Alternatives considered (preserved)

- **Docker-based sandboxing (the issue's leverage note):** impossible on this machine (no Docker daemon access); the OS-primitive envelope above is the honest best-available enforcement, with the compose `network: none` + dedicated-user posture recorded as where full enforcement lands (S35). The deviation is recorded here and in the PR rather than descoped silently.
- **RLIMIT_AS for memory:** rejected after probing — node v24 cannot boot below ~2 GiB of address space, so an AS cap tight enough to matter kills every node payload at boot; RLIMIT_DATA (heap/anonymous growth) contains real hogs while letting interpreters boot, and the cgroup memory.max layer supplies the kernel-OOM kill RLIMIT_DATA cannot.
- **A PTY for the terminal tool:** rejected — the S18 posture stands (no interactive input channel; the terminal tool is one-shot command execution, PRD §4.3/§20 no-takeover).
- **An always-async executor (every `executeProposal` returning a promise):** rejected — it would have forced the S20 scripted path (and every merged caller) into async-land for the in-process family that is synchronous by design; the OPTIONAL seam keeps both families honest on one path.
- **Per-execution `setuid` to a sandbox user:** rejected — unprivileged setuid is not a thing; the recorded posture is the runtime's unprivileged uid + the namespace mapping, with S35 owning the dedicated user.
- **Sweeping crash-orphaned `running` rows at boot:** left for the recovery slice (S31) — S22's `cancelForTask` sweep already terminalizes them on the next cancel; a boot-time execution-row sweep is recorded as the standing item below.
- **A new tool-history column for the artifact linkage:** rejected — the pointer rides the result text and the durable linkage is the artifact's producer_task_id/agent (S17's provenance); a schema change was not needed.
