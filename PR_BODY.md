# S29 — Memory: scopes, provenance, the publication boundary, and the write-time secret rejection

Branch: `s29-memory` (off main `1de68ae`, worktree `../shera-bot-s29`). Engineering record: [`docs/decisions/engineering-record-e42-s29-memory-2026-11-04.md`](docs/decisions/engineering-record-e42-s29-memory-2026-11-04.md) (E42); decisions index row + TRACEABILITY S29 section in the same docs commit. Implements PRD §11 and closes AC27 (agent-private memory never leaks into Operation context without explicit publication).

## Summary

- **Migration v21** adds the five STRICT tables (`memory_entry`, `memory_version`, `memory_publication_request`, `memory_settings`, `memory_agent_settings`), workspace-scoped (E12), no FOREIGN KEYs (the v4/v5 writer-validation discipline). The D37 scope vocabulary (`account | workspace | operation | task | agent_private`) is the storage layer's CHECK set; the visibility TABLE lives in the service.
- **AC27 is structural, not diligence:** an Agent-private memory's Operation-context visibility is a COLUMN on the row (`published` / `published_into_operation_id`) set only by the user's explicit `memory.publish_decision`. Publication shares into ONE Operation and never opens the private scope: the composed integration test pins the full arc — invisible to the other Agent's plain context, invisible in the shared Operation context, the typed cross-Agent 403 on the detail read, publication by the user, visible in THAT Operation's context only, still 403 on the detail, the thread never carrying the private content.
- **The write-time secret rejection is three layers, and nothing is stored on a rejection:** the EMBEDDED secretlint (`@secretlint/core` 13.1.0 + `secretlint-rule-preset-recommend` 13.1.0, both MIT, exact-pinned, footprint probed ~1.5 MB; the AWS ID-scan rule enabled; the embed proven to contribute — the bare GitHub-token fixture is caught only by the preset), the recorded S18/S25 redaction vocabulary re-expressed as detectors (key-assignment sweep with the CSV-doubled-quote alternative, PEM, bearer, Authorization, connection-string userinfo — attributed), and the entropy pass (≥ 32 chars, mixed classes, ≥ 4.2 bits/char — hex digests never trip). A scanner fault REJECTS rather than allows. A rejection leaves no row, no version, no event, no receipt — pinned by the whole-database byte scan (db + WAL + shm) over the full fixture table. The response names RULE classes only (G3).
- **Provenance is never optional (AC3):** zero source refs is the typed refusal for user writes AND automatic candidates, checked before anything exists. Automatic learning rides the typed contracts event `memory.candidate_proposed` (D37's payload verbatim; the proposing Agent is the envelope's actor; the scan precedes the journal so the event can never carry a secret — G2).
- **Sensitive publication carries the approval trail (G6):** a direct approve without a pending request is the typed `MEMORY_PUBLICATION_APPROVAL_REQUIRED`; approve/dismiss record who decided and when; agent actors are refused outright (`MEMORY_COMMAND_ACTOR_FORBIDDEN`).
- **The user controls (AC4–AC6):** version restore appends (edit → restore returns the previous content; history `created, edited, restored` preserved at the storage layer); auto-memory disable global AND per-Agent gates at the TOP of `proposeCandidate` (before provenance, before the scan) while explicit user writes are unaffected; permanent forget is a real DELETE of entry + versions + publication requests with the honest confirmation ("This cannot be undone — there is no restorable copy afterwards") — no contradictory "permanently forget — restorable" copy exists.
- **AC7 is a sweep, not a route:** the four read shapes are pinned — both Agent context reads, the direct detail read (the typed `AGENT_MEMORY_ACCESS_DENIED`, the S11 private-folder analogue), the Operation-context projection, and the spoofed retargeting query (refused by the strict schema, a 400). **AC8:** the pack-upgrade path (re-load, re-pin, re-seed over the same database) leaves the memory row byte-identical.
- **The S9 Memory surface (AC9)** renders the runtime's OWN record: the per-scope breakdown (all five D37 scopes grouped with their counts), the publication queue (approve/dismiss; the empty state teaches the boundary), the "Remembered from …" provenance lines with confidence and actor, version history with restore buttons, the honest two-step forget, publication controls shown only where publication applies, the auto-memory toggles, and the typed rejection displayed honestly where the action happened. The browser allowlist grows by exactly `GET /v1/memory` + `POST /v1/memory/commands`, the acting user bound SERVER-SIDE by the proxy's session binding; the Agent context/detail reads stay runtime-internal (the S11 folder-route posture).
- **Adopted dependencies (E-notes):** `@secretlint/core` 13.1.0 and `@secretlint/secretlint-rule-preset-recommend` 13.1.0, both MIT, exact-pinned; the lockfile diff is pure additions.
- **Process:** red-first per chunk (the red commits `7f2c4fa`, `56c0a66`, `c328ac3`), every chunk committed and pushed. The capture gate's interactive legs caught a REAL product bug before any capture existed — the browser commands' missing envelope fields (`command_id`/`idempotency_key`/`issued_at`) 400'd every browser-initiated mutation; fixed in the hooks with a per-attempt fresh idempotency key (D23 rule 6). The chunk-1 test initially pinned the wrong boundary twice (the contracts' strictness refusing an ownerless private create is STRONGER than the service backstop — both layers are now pinned where they live). No assertion was weakened to pass anywhere on the branch.
