## Decision and rationale

**Five READ_ONLY built-ins register through the SAME executor seam as every other family — the D35 ladder executes them automatically, and the research family is the network-ALLOWED side of the probed D27 separation.** The tools (`tool_web_search` capability `research.search`, `tool_page_fetch` `research.fetch`, `tool_document_parse` `research.parse.document`, `tool_spreadsheet_analyze` `research.analyze.spreadsheet`, `tool_image_understand` `research.describe.image`) are platform built-ins registered behind the composition's `researchTools` option (main.ts wires `SHERA_SEARXNG_URL` and the `SHERA_VISION_*` vision endpoint; absent configuration = that tool does not exist and the inventory answers truthfully without it, G4 — the workspace-file and page-fetch tools need no endpoint and register wherever the S17 sinks exist). Every declaration is the full contracts shape (AC7): version, input/output schema, capabilities, risk_class READ_ONLY, timeout, resource limits, redaction policy — and the E13 recovery class is DATA in both directions: the fetch tool DECLARES `idempotent_retry` (a GET re-run is safe) and the two parsers DECLARE `replayable` (pure functions of the bytes), while the search tool and the image tool OMIT the class and carry the stored `needs_human` default — the image tool deliberately so, because a provider call's retry semantics are the genuinely ambiguous case (the call may have consumed quota). AC8 is pinned end to end: a research proposal through the executor with the REAL S20 machinery wired answers `dispatched` → `executed` with NO approval row and NO grant.

**The bindings are the executor's async-dispatch family: network and file I/O never run inside the caller's SQLite transaction.** The sync `execute` is the typed refusal even with genuine authority (the S26 posture, E33's recorded seam); the async dispatch runs the work outside the transaction, the executor's cancel seam (ctx.signal) aborts in-flight requests, and the completion settles the row. The D27 separation is ASSERTED as the reason these tools may open sockets: the S25 suite composes, in one test, a real loopback fetch through the research binding (the socket demonstrably opens) next to the code-exec binding's spawn request carrying `networkDisabled: true` — the kernel-level route-table separation stays E36's pin, and this slice writes the two sides next to each other where the question "why may research open sockets" lives.

**Web search speaks the SearXNG JSON API; page fetch is readability + turndown; both are bounded by construction (AC3).** The search client is deadline-bounded, reads the body under a hard byte cap, validates the documented response shape (malformed entries skipped, never a crash), and refuses an over-cap response TYPED (`TOOL_RESPONSE_TOO_LARGE` — the search JSON cannot be truncated at a semantic boundary); the page-fetch policy is the opposite on purpose: a streamed body over the cap stops AT the cap and the readable head is real content — truncated-by-policy into an artifact with an explicit marker, never a refusal of work the tool actually did. Extraction runs @mozilla/readability over a linkedom DOM, converted by turndown to markdown; a page with no readable article degrades honestly to the raw page text behind an explicit marker (G4: the content IS there, the marker says the structured extraction found nothing). The scheme guard refuses anything but http/https BEFORE any fetch leaves the process (the no-SSRF-allowlist posture recorded under NOT verified). The deadline is the typed `TOOL_EXECUTION_TIMEOUT` (pinned with a real deadline abort against a slow-streaming fixture).

**Document and data tools read the S17 ROW-BASED workspace store — the same surface the panel reads — and every parse writes its artifact.** The uploaded-file tools take `workspace://` URIs, read bytes through `WorkspaceFilesRepository.read` with the EXECUTING AGENT as the storage actor (the shared scope readable, another Agent's private folder the typed denial it already is, D39), and map the storage layer's typed errors onto the research vocabulary (`WorkspacePathError`/`PrivateScopeDeniedError` → `RESEARCH_INPUT_INVALID`, `WorkspaceNodeNotFoundError` → `RESEARCH_SOURCE_NOT_FOUND`). PDFs parse through unpdf (merged pages); text/markdown pass as themselves; unsupported formats refuse typed with the supported set NAMED (no docx parser — outside the recorded leverage list). Spreadsheet analysis is DETERMINISTIC statistics over SheetJS CE rows — sheet shape, per-numeric-column count/min/max/sum/mean — never a model call; the full table becomes the structured CSV artifact. Both tools write their result artifact on EVERY successful parse (the issue's "structured text/table artifacts with provenance"), producer run + agent stamped, bytes REDACTED before the sink.

**Tool-history honesty is structural (AC4/AC5/AC6).** Arguments are recorded only through the executor's digest + redacted bounded summary (G3 — the bindings never write history); the result text carries the ARTIFACT POINTER FIRST (the executor bounds the recorded summary — the reference must survive the bound, the content head follows), the bounded head, and truncation markers where policy cut content. Large fetched/parsed content becomes an artifact with provenance and the prompt head stays bounded (8 KiB; the AC4 test asserts the bound with a ~90 KiB page). Every failure is a typed error whose retryability is ONE truth in two pinned tables: the research failure shapes (`TRANSIENT_NETWORK` retryable; `TOOL_RESPONSE_TOO_LARGE`, `RESEARCH_INPUT_INVALID`, `RESEARCH_RESPONSE_INVALID`, `RESEARCH_SOURCE_NOT_FOUND`, `RESEARCH_SOURCE_UNREADABLE`, `RESEARCH_PROVIDER_UNAVAILABLE` not) and the S22 retry classification were extended together and are pinned to agree; the S22 bounded policy retries a transient failure (1s/2s/4s, exhaust → the recorded `retry_exhausted` pause) and fails a permanent one immediately (AC6 pins both, plus a live re-propose executing after a 503 fixture failure). Image understanding rides the S23 AI SDK vision seam with `maxRetries: 0` — the E33-era lesson: a silent SDK retry would multiply provider calls and stretch the tool's own deadline; the RUNTIME owns retry decisions.

**The redaction boundary covers the DERIVED artifacts, not just the history row (AC5).** `redactArtifactText` (the S18 vocabulary then the tool-layer entropy pass, without bounding) runs at the binding boundary BEFORE the artifact sink — the executor's later pass covers only the history row, not artifact bytes, so this is the boundary that makes derived files clean by construction. The AC5 pins: for FETCHED content (the secret enters the runtime ONLY through the tool) a whole-database byte-scan over runtime.db + WAL finds no planted shape — key assignments, quoted-key JSON, Bearer, Set-Cookie, and a bare high-entropy token; for UPLOADED files (the user's own row legitimately keeps the user's bytes) the derived surfaces are pinned clean — history rows, journal payloads (read through the repository surface; the boundary guard caught and corrected an inline-SQL draft of this test), and artifact bytes — and the agent-memory table stays empty (tools never write memory; read through the repository surface). One REAL leak channel surfaced during the pin and was fixed at the vocabulary: a JSON snippet inside a spreadsheet cell returns from the SheetJS round-trip with CSV-DOUBLED quotes (`""password"": ""value""`), and the recorded quoted-value alternative matched only the empty `""` prefix, leaving the value readable — the S18 key-assignment sweep gained the doubled-quoted-value alternative (additive; undoubled JSON matches exactly as before; the S21 precedent of recorded vocabulary extensions; every S18/terminal pin stayed green).

**The UI is the EXISTING truthful surfaces — the taste pass refined, never redesigned.** The research tools render through S21's Settings → Tools inventory (owner, scope, risk badge, permissions, disable switch — the research tools appear as built-ins with their capabilities and READ_ONLY posture) and the workspace panel's Tool history tab (the executor's redacted rows). The capture harness (`capture-s25.mjs`) drives the REAL web app against the REAL runtime with all FIVE tools actually executed through the ONE path (a local deterministic SearXNG fixture + a deterministic mock vision model — G7), files seeded through the real upload route, from the PRODUCTION build. The adversarial taste pass on the rendered result found two defects, both fixed and recaptured in one confirmation round: the artifact pointer rendered as `artifact artifact…` (the id slice took exactly the literal prefix — now the id stem) and the multi-line transcripts collapsed into run-on paragraphs (the row now renders with `whitespace-pre-line`, keeping the recorded structure). Captures under `apps/web/.impeccable/review/s25/`: tools inventory 1440/768/360, tool history 1440/768/360, reduced-motion on both surfaces, keyboard-only focus with the tab trail (JSON), and the AC2 evidence — `manual-runs.md`/`manual-runs.json` recording one REAL manual run per tool with its redacted transcript, the fixture posture stated in the file.

## Alternatives considered (preserved)

- **A SearXNG client library or any code-level SearXNG dependency:** rejected — SearXNG is AGPL; the recorded posture is an UNMODIFIED EXTERNAL container over HTTP with no code linking. The client in `searxng-search.ts` speaks the documented JSON API shape and nothing else.
- **Self-hosting pdf.js / SheetJS forks for the CVE posture:** rejected for this slice — unpdf bundles pdf.js serverlessly (the recorded leverage), and SheetJS CE 0.18.5 is what npm serves; the upstream 0.20.x fixes distribute via cdn.sheetjs.com, a different resolution channel — recorded as the owner item rather than silently pinning a non-registry tarball behind a frozen lockfile.
- **A per-tool retry loop inside the executor or the bindings:** rejected — the runtime's retry policy (S22) owns retries at the RUN level; the tool surfaces the typed retryable code and the coordinator re-drives (the AC6 re-propose pin). The AI SDK's `maxRetries: 0` keeps each provider call one-shot.
- **The whole-database byte-scan for the uploaded-file leg:** rejected as the only pin — the user's uploaded row legitimately keeps the user's bytes (it IS the user's file, stored by the user's own upload action, not tool output); that leg pins the DERIVED surfaces (history, journal, artifacts) while the fetch leg — where the secret enters ONLY through the tool — carries the whole-database pin.
- **Rendering tool results as preformatted blocks or HTML in the UI:** rejected — `whitespace-pre-line` keeps the executor's recorded transcript verbatim; anything richer would re-render what the runtime already bounded and redacted (the UI shows the record, never its own reconstruction).
- **A docx parser:** rejected — outside the recorded leverage list; `.docx` uploads refuse typed (`RESEARCH_SOURCE_UNREADABLE`) with the supported set named. Extending the format set is additive.
