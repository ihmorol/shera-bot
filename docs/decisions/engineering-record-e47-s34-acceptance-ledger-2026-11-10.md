## Decisions

1. **The S28 fix pins the clock AT the fired dueAt, not just below it.** Alternatives: pinning below (e.g. `T08:59:59Z`) or pinning "now" to capture day — rejected: at the dueAt, `max(now, dueAt)` is exactly the occurrence instant, the next-occurrence math is deterministic by the scheduler's own documented semantics ("strictly after the one just fired (and after now)"), and the trigger's bookkeeping records the firing time the test actually simulated. The alternative of editing the line-278 literal (2026-11-09 → 2026-11-16) was REJECTED outright — it would have re-failed after 2026-11-16 (the same drift, deferred) and hidden the missing-clock root cause. This is the same clock-injection idiom the S30 review round applied to the sibling scheduler-reconcile suite (its commit 7d72c43); the S28 autonomous-proof suite was missed there because its compose call did not thread `now` at all.
2. **The axe critical/serious findings were FIXED, not waived.** The spec's recorded rule is "critical/serious axe violations must be fixed, not waived" (the run fails otherwise; moderate/minor are recorded in the JSON evidence, never silently dropped, never inflated into failures). Alternatives: scanning axe with the color-contrast rule disabled, or waiving the two nodes in the ledger gaps — rejected: both are real WCAG AA failures on the primary action buttons of the shipped product; the honest repair is the token-level fix above, surfaced to the owner through this record (UI_DESIGN §2.1 says exact values are "the starting point; the owner's sketch may adjust accents" — the owner's verdict stays open, as on every row).
3. **The keyboard spec asserts the accessible name, not an aria-label attribute.** The dead builder's assertion was written against a component it over-specified: the shipped link is content-labelled, which axe's meaningful-label rule accepts. Alternatives: adding a redundant `aria-label` identical to the content — rejected (attribute noise with no a11y gain, and a MIS-matching aria-label would re-introduce the mismatch finding).
4. **The harness is surface QA over frozen fixtures and says so everywhere it renders.** Alternatives: driving the real Next.js dev server with live runtime state — rejected for the tier-2 posture (E43: hermetic, deterministic, scorers over frozen snapshots; the live-runtime journey legs are the vitest rows, e.g. AC7's mock-runtime E2E). The harness mounts the REAL shipped components (login page, chat thread, approval card + decision modal, settings views) with next/link and next/navigation stubbed; a `pending-owner` leg on AC20 keeps the real-device pass open.
5. **AC13's JSON-vs-doc contradiction was closed by mapping, not by editing the doc down (G5).** The ledger doc's AC13 row has claimed a browser-matrix approval leg since the in-flight draft, but the JSON mapped none — the runner would never execute the claim. Alternatives: deleting the claim from the doc — rejected: the approval card/modal journey is real automated evidence in real browsers; `journeys.spec.ts` is now mapped on AC13's row (the report shows it green per project) with a covers line naming what the same spec additionally walks.
6. **AC21's PENDING_MERGE pin was resolved by the MERGE itself, and the pin history is kept.** The S27 branch merged to main as PR #82 (da3019b) — E45's own record names the S34 flip as the merge's consequence.
