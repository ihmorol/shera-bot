## Decision and rationale

**The executor is the ONE runtime-owned execution path, and it is now real.** A typed `tool.proposed` envelope (D26, digest-only — G3) rides the existing harness seam into `ToolExecutor.executeProposal`, which resolves the tool through the runtime registry (contracts-parsed definitions; an unknown tool is a typed refusal with NO history row — writing one would require inventing a risk class, and classification is data, never prose — G2), refuses a disabled tool BEFORE any grant consult (AC6), validates raw arguments against the tool's own input schema, ties the execution to the journalled digest (when the runtime holds raw args; the scripted demo path carries no args and trusts the journalled digest — the documented posture), resolves the risk class from the D35 ladder TABLE (`RISK_CLASS_LADDER` — every D9 class mapped to its execution posture and preview kind; capability prefixes `code.*`/`repo.*` refine the preview kind, still data), and executes through the resolved binding. Bindings refuse to run without the executor-minted execution authority (a module-private brand), and the harness sink handed to adapters exposes exactly `propose` — both pinned (AC1: no bypass path reachable from agent-facing code).

**The gated branch consults the S20 machinery and fails closed.** For every non-READ_ONLY class: a deterministic grant fast-path (the run's task-principal grant, then the agent-principal grant — the first ACTIVE match wins; `checkExecutionAllowed` skips the prompt, never the policy check) executes immediately and consumes a one-time grant after the effect (`consumeOneTimeGrant`, new public method, consumption stays post-effect); without a grant the executor builds the pure preview (binding `preview()` is pure, redacted and bounded BEFORE any row exists — AC2's preview-before-write), records the awaiting history row with the approval linkage, and pauses the run through `createRequestFromTypedProposal` — the real execution is WITHHELD in an in-memory registry keyed by approval id, and runs ONLY when the decision machinery's post-commit callback invokes `runWithheld` (AC3, both sides: nothing pre-decision on the pause path, the effect only after the approve transaction commits on the decision path). Without the approvals machinery wired at all, the gated branch refuses (`TOOL_APPROVAL_UNAVAILABLE`) — never un-gated execution.

**Per-tool limits are record fields, not global guesses (AC5).** `timeout_ms` and `max_response_bytes` live on each runtime tool record; the deadline is cooperative for the in-process binding family (bindings check the injected clock between work units — the executor post-checks for drift) and the response budget is executor-enforced, both with typed errors (`TOOL_EXECUTION_TIMEOUT`, `TOOL_RESPONSE_TOO_LARGE` — an oversized result is refused and stored nowhere). The D27 resource-limits object rides the record into the binding context; kernel-level enforcement (memory/processes/disk) lands with the process-backed family (S26) through the same interface, with the cancel seam (`ctx.signal`) as S22's escalation hook. The E13 recovery class is stored data end to end: the contracts field defaults to `needs_human` at the schema and column layers, the executor never invents one, and every history row exposes it (AC4).

**Agent-created tools (E4) live inside the D38 intersection.** Creation is preview-gated (a pure read model resolving the ladder entry and the D38 verdict — zero rows; the create command re-validates everything, preview answers never trusted, D30/D36): a tool whose declared capabilities fall outside `PLATFORM_TOOL_CATALOG` (the platform layer) or the pinned pack's allow-list union resolved through that catalog (the pack layer) is refused with the refusing layer NAMED (AC7). READ_ONLY creations auto-activate for the creator (E4's non-destructive posture); risky ones land in `created` and stay unexecutable until activation. Activation is a RUNTIME GRANT: any agent actor — including the creating Agent for its own tool — is refused before any state check (AC8, G6), and a user decision records the activation grant in the one runtime place, idempotently (duplicates unrepresentable at the primary key). The executor consults the lifecycle for agent-created tools: `TOOL_NOT_ACTIVATED` without an activation grant targeting the proposer (or workspace-wide), `TOOL_NOT_SHARED` for private-scope tools. The disable switch writes a workspace-scoped disablement the executor consults before grants — disabling beats a grant end to end (AC6).

**Redaction is one boundary layer extended, applied before any write (G3/AC9).** `tool-redaction.ts` reuses the S18 terminal-boundary vocabulary verbatim (the S18 review round's quoted-key JSON + `cookie` families included) and adds the tool-layer extension the terminal surface deliberately lacks: a high-entropy-run pass (24+ chars mixing letters and digits) for bare opaque secrets in tool results and argument summaries, plus explicit truncation markers. The executor redacts the preview text, the side-effect summary, and the resource scope BEFORE the approvals boundary (whose own S20 pass predates the S18 quoted-key vocabulary — the executor closes that gap at its boundary; the boundary's pass still runs, defense in depth), computes the recheck scope through the same single redaction point, and bounds every recorded surface. Pinned by secret-shaped fixtures: no raw secret reaches the history rows, the approval request, the journal events, or runtime.db/WAL (a whole-database byte scan, the S18 pattern).

**MCP TypeScript SDK (the issue's leverage note): read, designed for, honestly scoped.** The MCP docs (modelcontextprotocol.io — tools/list, tools/call, JSON Schema input/output, annotations untrusted, "clients SHOULD validate inputs, implement timeouts, sanitize outputs") were read BEFORE the design. The binding contract is the MCP seam: one binding per wrapped server, with validation, limits, risk gating, redaction, and history happening in the runtime executor before any `tools/call` leaves the runtime (G2 — the executor stays authoritative). Live MCP-server wrapping over stdio/Streamable HTTP is NOT in this slice — none of the 10 ACs exercise a live server, and the platform's research/execution tool families (S25/S26) are where real MCP servers arrive. The scoping decision is recorded here, not silent: the seam, the Zod/JSON-Schema tool records, and the per-call timeout/response discipline are all in place for it.

**UI.** Settings → Tools (UI_DESIGN §S9): the truthful inventory (owner, scope, risk badge, capabilities, version, lifecycle state — the switch state and the state row agree, a taste-round fix), the preview-gated creation flow (preview resolves the D38 verdict and names the refusing layer; create re-validates; risky tools await the user's activation decision), and the disable switch that actually prevents execution. The workspace panel gains the Tool history tab (the S7 tab list closes): executor-recorded rows with the status vocabulary (proposed → running → succeeded/failed/blocked/awaiting_approval — §7 copy, never the UI's guess), the redacted arguments summary, the preview, the result, and the approval linkage. Tool call cards hydrate the runtime's own status by (task, tool, args_digest) — the digest IS the arguments identity both surfaces carry — and without history they show the event-only truth (G2: never "done" before the runtime says so). The browser surface adds exactly the five tools paths to the allowlist: two GETs (inventory, history) and five POSTs minus execution — tool EXECUTION has no browser route at all; the four mutations bind the user actor server-side (the S20 security pattern).

## Alternatives considered (preserved)

- **Approving a gated tool by re-proposing after the decision (test-time shortcut):** rejected — the production callback IS `executor.runWithheld`, driven by the approvals API's decide hook; the tests drive exactly that path.
- **A history row for unregistered tools:** rejected — it would require inventing a risk class the runtime does not know (classification is data, never prose, G2); the unknown-tool refusal rides the run's typed-rejection path instead.
- **Registering the student pack's five catalog tools as executable inventory:** rejected for this slice — their families (web search, code exec, repo push) have no implementations until S25/S26; the inventory lists what the runtime actually owns (the real note-tool family), and the pack's tools remain catalog metadata driving the D38 pack layer. Fake-completion inventory rows would violate G4's spirit.
- **Async bindings now:** rejected — the in-process family is synchronous, which is what preserves S20's consumption-after-effect ordering; process-backed bindings (S26) arrive through the same interface with their own supervision posture.
- **Extending the contracts vocabulary with tool.* execution events:** rejected for this slice — the executor history table IS the durable record (the E30 precedent: contracts stay untouched unless the product requires it), and the tool history API + panel tab are the read surfaces.
- **The MCP SDK package embedded now:** rejected (recorded above) — no AC exercises a live MCP server; the seam is typed and the wrapping is S25/S26 work. No new dependency was adopted in this slice (playwright was already adopted at 1.64.1, Apache-2.0, on the S01 reviewed allowlist).
