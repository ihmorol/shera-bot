## Summary

- **Migration v20** adds the seven STRICT tables (`credit_account`, `credit_transaction`, `usage_record`, `cost_estimate`, `reservation`, `settlement`, `release`), workspace-scoped, no FOREIGN KEYs (the v4/v5 writer-validation discipline). The available balance is DERIVED (`granted − charged − reserved`) from three non-negative CHECK-constrained counters — never a stored column that could drift; an under-estimate honestly overdraws and the next reservation refusal reads the negative.
- **Reserve → settle → release** runs in ONE SQLite transaction per movement (D10): typed exactly-once settlement, actual-usage settlement (an unused estimate releases as its own row with reason `unused_estimate`; an under-estimate charges the actuals), and corrections as NEW `adjustment` rows bounded by the original — the ledger has no UPDATE/DELETE path anywhere (AC9 is structural, pinned at the repository).
- **The ledger sits BEHIND the recorded seams and the seams are the only funders:** the S28 fire pipeline claim → reserve → gate → run → walk → settle consults the real derived balance and a refusal pauses the run BEFORE anything executes; the S32 top-up grant + D8 `resume_task` re-drives the paused run to completion (`resumeRunAfterTopUp` — AC2; E38's "the grant record IS the seam S24 will consult" closed without changing S32's contract); the S22 cancellation path releases every active hold through the recorded `credit_reservation_release_requested` hook (`task_cancelled`). No second funding or spending path exists.
- **D48 pinned as the pause, not the queue:** a refused reservation transitions the run to `paused` with `pause_reason = insufficient_credits` — explicitly NOT an E1 `QUEUED` capacity placement (contract test pins the negative). Visible in the run state, the schedules surface, and the exhausted-credit pause card with its unblocking paths in product language.
- **E13 ambiguous outcomes HOLD the reservation** into `RECOVERY_REQUIRED` (no blind retry, no silent release; the outcome recorded on the run's stream); a clean never-landed provider failure releases with reason `provider_failure`.
- **AC7: credits gate model calls ONLY** — an exhausted account still completes tool legs (S21 executor), file writes, and approvals; custom-provider calls consume zero Shera credits but record usage/latency with `charged_units = 0`.
- **AC8 UI renders the ledger's OWN numbers, never recomputed client-side:** the sidebar credits pill (remaining + reserved on hover AND keyboard focus via the same reveal path; the exhausted pill names its unblocking path in words) and the S9 "Model budgets / Credits" settings surface (headline row, per-run drill-down rendering each run's movement rows verbatim, custom-provider zero block, the exhausted-pause card leading the surface when it applies, a not-yet-provisioned account saying so instead of fabricating a zero). The browser trust boundary grows by exactly two GET reads (`/v1/credits`, `/v1/credits/runs/:run_id`) with NO mutation route by construction (grants ride S32's authenticated seam), pinned by the runtime-access contracts suite.
- **No dependency adopted:** `pnpm-lock.yaml` is byte-identical to main; the OSS billing library was explicitly rejected per the issue's recorded leverage note.
- **Process:** the first builder died mid-UI-chunk at a provider error; chunks 1–4 were complete and green and were audited (not restarted); its WIP was preserved as `a4ea015`; the continuation builder resumed red-first (the AC8 numeric pin + the taste-pass copy bar at `a58ba4f`), fixed copy (`b54a720`), landed the production-build capture gate (`d544ddf`), cleared lint/format debt (`3eca675`), fixed the a11y finding the full suite surfaced (`ecba0a6`), merged main for PR #74's S28 fixture clock pin (`9b653c3`), stamped the merged file's format debt the gate caught (`8a3be03`), and filed the record + index + traceability (`a5cd1cd`, `e08bfe6`, `53c817a`).
