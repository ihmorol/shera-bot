### S27-GAP-1 (issue #83) — the setsid grandchild survived the group kill

- **Red-first**: the ST-04 detached leg was committed RED on the unfixed tree (`tests/security-evidence/2026-11-10-gap1-setsid-red.txt`; the escapee pid alive past the typed cancellation — the recorded gap reproduced in-suite), the fix landed next commit, the suite 2/2 (`…-green.txt`). The pre-existing group-kill leg untouched and green throughout (G5: nothing weakened).
- **The fix** (`adapters/process/escape-sweep.ts` + the `killTree` wiring in `execution-process-spawn.ts`): at cancel(), the wall clock, and the post-exit reap — (1) the PPid chain walked BEFORE the group kill while intact; (2) the escape sweep: /proc scanned for processes that are NEW in the execution's window (a spawn-time pid→starttime snapshot; the starttime compare is the pidfd-reuse-safety stand-in — Node exposes no pidfd syscall surface, a native FFI dependency rejected per E15, recorded here), are their OWN session leader (sid === pid — the only shape setsid(2) produces), and INSIDE the execution's own user namespace (the leader's PRIVATE uid_map — the D27 `unshare --user` envelope's "0 <uid> 1"; the HOST map means no namespace and the sweep does not run — a control that cannot scope itself does not run, G5); (3) verified kills (starttime re-checked at kill time — pid reuse spared). The uid_map read is LAZY and cached (probed live: at spawn-return the fork is pre-exec and carries the host map; the private map exists only after unshare(2) runs).
- **Why it is safe next to concurrent executions**: the uid_map condition excludes every process outside the execution's namespace — the vitest workers, sibling suites, and system daemons carry the host map and can never be swept (the hazard was identified and closed in design, before any test ran against the sweep).
- **The residual (recorded in SECURITY-GAPS §GAP-1, THREAT-COVERAGE, and the runbook §9)**: a double-fork orphan completing inside one sweep window without setsid; an escapee nesting its own user namespace; a leader without a private map (sweep disabled — honest degradation). These close with PID-namespace containment at spawn on the deployment host — runbook §9, Manual decision 6.
