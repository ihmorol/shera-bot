## Decision and rationale

**The operator surface is ONE authenticated API plus a thin CLI over it — never a second path.** Every operational capability is an Express route under `requireAdminToken` and wrapped in `adminHandler` BY CONSTRUCTION: the wrapper records the `admin_action`/`admin_action_failed` security event (actor = the token id, action, target account, correlation id, redaction-classed details) for every call, success or failure — AC6 is structural, not per-route diligence. The CLI maps 1:1 onto those routes (`callAndPrint`); it prints the typed error body (`code` + `safe_message`) on failure and exits 1, maps commander usage failures to exit 2, and never has a side channel. Where an operation must REACH the runtime (emergency cancel, the credit-top-up resume), it rides the recorded S06 internal channel with the per-container credential — no second channel, no control-plane-side shortcut.

**The admin token lifecycle is local, hash-only, and displayed exactly once (AC5, G3).** `token create`/`token rotate` are LOCAL operator operations against the control plane's PostgreSQL (they require `DATABASE_URL`, not the API): the 32-byte random token (prefix `shera_admin_`) is generated once, displayed once alone on stdout (guidance on stderr), registered with the secret registry for value-based redaction, and stored ONLY as its SHA-256 digest plus a 12-hex digest hint. Verification is a constant-time digest comparison; a missing/unknown token is refused typed (`ADMIN_UNAUTHENTICATED`) and recorded as `admin_auth_rejected` WITHOUT the presented value. Rotation revokes the previous token immediately; at most one token is active, so a lost token is recovered by creating a new one (a rotation by effect — the old digest stops verifying, pinned end to end). The CLI resolves the token from `SHERA_ADMIN_TOKEN` or `--token-file` — NEVER an argv flag (argv is world-readable) — and the redaction test pins that no output line on any path (typed errors, 401s, usage text) ever contains the credential; the CLI's non-JSON error fallback is a bounded 300-character prefix, reviewed here as the honest middle between G4 silence and echoing an unvetted body (JSON typed bodies are parsed and printed as `code`/`safe_message` only).

**AC7 posture: administrator status is DB-managed and there is no write route anywhere.** The `is_admin` flag has no API or CLI granting path — bootstrap happens on the control-plane host with database authority (the `token` commands ARE that local authority, and they mint credentials, not administrator status). Pinned by the admin-flag suite.

**The capability surface (the canonical CLI command table — the promise the test comment records).** Global flags: `--url <origin>` (or `SHERA_CONTROL_PLANE_URL`) and `--token-file <path>` (or `SHERA_ADMIN_TOKEN`), accepted program-level or per-command. **Emergency cancel is isolation-scoped and borrowed, not reinvented (AC4).** The admin route resolves the target account's runtime over the recorded channel and drives the runtime's OWN S22 `RunCancellationService` (`/internal/v1/admin/cancel-all`, tenant-checked against the channel's bound account) — parent, child, and queued work stop for THAT user; the isolation test runs two REAL composed runtimes behind fake containers and asserts the other user's work untouched. An unreachable runtime is the typed `RUNTIME_UNAVAILABLE` — no partial success is reported.

**The honest seams (G4 — recorded here as the slice's contract).** (1) BACKUPS: the trigger and the restore request are RECORDED (`requested` status; snapshot refs minted, listed, restore requested per E11) — the mechanism that produces or restores a snapshot is S33's; no response claims a completed backup. (2) CREDITS: the top-up writes a durable central grant record (`control_credit_topups`, integer positive amount, redacted reason, correlation id) and then applies the D8 `resume_task` through the runtime (PAUSED → QUEUED, admin actor) — runs paused for another reason come back as TYPED skips (`pause_reason_not_insufficient_credits`, `resume_refused`), never silently claimed resumed. The committed-grant/failed-apply window is truthful by sequencing: the runtime target resolves FIRST (typed 503 before anything commits), the grant commits, then the apply runs; a failed apply after the grant committed is a typed failure the operator can re-issue (applying is idempotent in effect). The S24 credit ledger does not exist yet — the grant record IS the seam it will consult (pinned here; the CLI-level pin drives a REAL composed runtime: one run resumed, one run typed-skipped, the grant row asserted). (3) CONTAINER VIEWS: on an engine-less host the commands answer the typed errors (`RUNTIME_PROVISION_FAILED` with no backend at all, `RUNTIME_NOT_PROVISIONED` for an unprovisioned account, `RUNTIME_UNAVAILABLE` for an unreachable backend) or the RECORDED state last synced — the usage view reads the applied tier limits and the bounded health summary and never invents live metrics.

**No console UI (AC8).** The branch touches ZERO files under `apps/web` (`git diff --stat 707b11e..HEAD -- apps/web` is empty; 42 files total across apps/control-plane, apps/user-runtime, packages/contracts, docs, pnpm-lock). D47/E7 stand: the console is production-gated.

## Alternatives considered (preserved)

- **An argv flag for the token (`--token <value>`):** rejected — argv is visible in `ps` and shell history; the token arrives via env or `--token-file` only.
- **Storing the raw (or encrypted) token:** rejected — hash-only SHA-256 with the exactly-once display; an encrypted-at-rest token would still put the credential one key away from every surface G3 guards.
- **An `is_admin` write route (even owner-token-gated):** rejected — AC7 wants no non-owner granting path to EXIST; bootstrap is a local DB operation by design.
- **A separate admin transport/channel to the runtime:** rejected — the recorded S06 internal channel already carries authenticated per-container administration (S22's cancellation, the D8 resume); a second channel would duplicate custody and audit.
- **A fabricated credit balance/ledger:** rejected — G4; the durable grant record plus the recorded resume path is the honest seam until S24's ledger lands.
- **Executing backups/restores in this slice:** rejected — E11 records the split (trigger here, mechanism in S33); executing without the mechanism would fake the effect.
- **A compiled JS bin shim (compile step for the CLI):** rejected — the repo runs TS directly (the control plane's `start` script is `node src/main.ts`); converting parameter properties to explicit fields keeps the whole CLI closure strip-compatible with plain Node 24, so no shim and no build step is needed. `pnpm exec shera-admin` does not work in the workspace (pnpm exposes a package's own bin only to dependents — verified, documented honestly in the CLI reference).
- **Test-only: importing the E20 `temp-resources.ts` helper across apps:** rejected — a cross-app TEST-helper import has no precedent and boundary exceptions are allowlisted individually; the one-function control-plane helper replicates the E20 shape with the reason documented in-file.
