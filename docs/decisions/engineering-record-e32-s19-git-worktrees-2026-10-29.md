## Decision and rationale

**The runtime owns git; the coordinating Agent prepares, the user decides, the runtime merges.** `GitService` (apps/user-runtime/src/modules/git) is the container's git coordination seam: project import/clone, per-repository credentials, task-scoped branches + worktrees, the conflict queue, and the approval-gated merge. Every mutation is a runtime operation on typed input (G2); there is no push code path at all — the only repository-history mutation is the local merge, and a static scan test pins that no force form (`--force` in any dashed form, `forcePush` identifiers, short-flag pushes) appears anywhere in non-test user-runtime source (E6: the runtime never force-pushes or silently merges).

**Projects arrive three ways and are shared by default.** Import from a git URL (with an optional one-time D22 credential), from a local directory (history preserved when already versioned), or from a zip/tar/tar.gz archive snapshot (v16 widens `source_kind` to admit `archive`). There is no project-count limit (capacity is the container). `access_mode` is `shared` (the PRD §10 default) or `restricted`, where a `project_agent_access` allowlist (replaced as a whole by the writer) gates worktree allocation with a typed 403. Import/clone is ATOMIC: the staging tree is built first, the row is inserted last, and any failure removes the staging tree and registers nothing (pinned by clone-failure, hostile-archive, and missing-file tests).

**Repository credentials are vault custody (D22/E9), never URL material.** `CredentialVault` seals each secret with AES-256-GCM (12-byte random IV + GCM auth tag, three BLOB columns, `key_version` for future rotation) under a container-local 32-byte key file written owner-only (0600) beside the database; a missing key is generated once, an unreadable existing key is a typed hard failure (never a silent re-key that would orphan ciphertexts), and tampered or foreign-key decryption fails closed. The API answers masked hints only — `maskSecret` reveals the final four characters only at length ≥ 12 — and there is deliberately NO read-back route. `sanitizeGitUrl` strips `scheme://user:password@` userinfo for persistence (SCHEME-AGNOSTIC after the review round: an `ssh://user:pass@…` URL is refused at import exactly like the https form, while the scp-like `git@host:owner/repo.git` form — standard syntax without a password — passes untouched). `buildAuthenticatedUrl` injects the credential into https URLs at CALL time only and refuses every other scheme, so a local `file://` path can never collect a secret. A revoked credential fails safely with a typed refusal BEFORE any git call (pinned end to end over a loopback http origin); replace = revoke-first, enforced by the v15 partial UNIQUE index (one ACTIVE credential per project+kind). A git-level failure is typed with no git error text, which could quote an authenticated URL (G3). The G3 at-rest byte-scan test reads the raw SQLite file and the key file and asserts the raw secret appears NOWHERE in durable state or the fault log.

**Isolated workspaces with a conservative conflict queue (D6/E6, G5).** Each admitted coding task gets `shera/task/<task_id>` (segment-sanitized) plus a dedicated worktree under the container-local projects root; the default branch is untouched until an approved merge (AC17, pinned on real git state). THE CONFLICT QUEUE IS A STORAGE-LEVEL INVARIANT: a v15 partial UNIQUE index admits at most ONE ACTIVE worktree per (workspace, project), so two tasks can never hold the same project simultaneously — a second task's request is RECORDED as a `queued` row whose visible `queue_reason` names the holder, never granted concurrently; the queue is honest state, re-answering idempotently, and queued entries are marked admitted in the same transaction that inserts the winner's row. This is the CONSERVATIVE per-project-exclusive reading of D6 ("related conflicting work queues"); worktree-path-level or task-path-lease widening is possible at integration without schema change (the status vocabulary already carries `queued`/`admitted`), and the PR records that integration may widen it.

**Merge requests are computed from the real repository and filed through the ONE approval machinery (D9/D35, no parallel path).** `prepareMergeRequest` computes the PRD §10 fields from real git — changed files via the merge-base diff, commit count via rev-list, conflict status via `git merge-tree --write-tree` on the object database alone (no working-tree mutation) — then files the D9 approval through `ApprovalsService.createRequestFromTypedProposal` with the row + approval as ONE transaction (a transition rejection rolls the row back — nothing half-prepared). The approval's `args_digest` pins the exact change set (project, branches, head commit, sorted changed files) the user is shown approving. The three PRD §10 choices relay onto the D9 vocabulary through the S20 `ApprovalsApiHandle.decide` — approve → `approve-this-execution-only` (one-time, args-pinned), reject AND request-changes → `reject-this-action` (the D9 record keeps its contract vocabulary; the merge-request row records the PRD §10 `rejected`/`changes_requested` state) — there is NO parallel approval path. An AGENT actor is refused by the S20 service itself (403, never self-approve, G6 — pinned at the route), and the browser proxy rebuilds `decided_by` from the authenticated session server-side (the E30 security pattern extended to the new decision route).

**The approved merge executes only after the decision transaction commits.** The composition's `executeForApproval` seam attaches the real gated action to an approval whose request resolves to a merge request: the closure (a plain `git merge --no-ff` — no rebase, no force) runs only after the approve decision's transaction commits (the S20 rule), and `performMerge` independently re-checks, in order, the linked approval's resolved-approved status, the request's lifecycle (idempotent on replay), and a clean target working copy. An execution-time conflict aborts the merge — the target branch left exactly as it was — and records the failure on the row (G5); the post-merge release frees the project's slot for the queue (a release failure is a recorded fault, never a failed merge). Reusable grants are never created from merge decisions (the relay offers one-time approval only), so the resource-scope choice — `git://<sanitized project name>/branches/<target>`, chosen over a UUID because the approval boundary's entropy redaction would render a UUID-bearing scope unreadable — has no cross-project grant-match surface in this slice; the grant-ladder slice must revisit the scope choice before wiring reusable merge grants.

**The validation runner executes the project's DECLARED validation (G2).** Detection is the documented Node heuristic: the repository's own package.json scripts, from the fixed priority list (`test`, `lint`, `typecheck`), run sequentially with the lockfile-chosen package manager; a repository declaring nothing answers `not_run` with an honest note — commands are never invented. Commands run inside the task's worktree (the exact tree the merge would land) with a per-command timeout; failing output is condensed to a tail and pushed through the SAME deterministic secret-redaction pass the approval boundary uses before entering durable product state (G3). A validation failure is recorded, never blocking on its own: the merge stays approval-gated.

**The archive import is a hand-rolled, bounded reader (the security-sensitive surface).** The supported surface is deliberately minimal (zip: EOCD + central directory + local headers, stored and deflate entries; tar: ustar, GNU longname, pax `path` override only) and everything else is refused TYPED, never guessed at. Every entry name passes the guards — no absolute paths, no drive letters, no `..` segments, no control characters (the deliberate `no-control-regex` suppression is the guard itself), length-bounded, backslashes normalized FIRST — plus: no `.git` entry anywhere, symlink/hardlink entries refused outright (a link escape is unrepresentable), per-entry declared size checked BEFORE decompression, the whole tar.gz stream capped WHILE it decompresses (the review-round fix: `gunzipCapped` refuses a gzip bomb mid-stream instead of inflating it into memory first), total-bytes and entry-count caps, and a refuse-writes-nothing atomicity the git service composes with. The single common root folder ("download ZIP" shape) is flattened with a collision check.

**The web surface renders exactly the recorded review.** Settings → Git (UI_DESIGN §S9) lists the workspace's real repositories with the worktree ledger (the G5 queue visible with its reason) and merge-request cards rendering exactly the minimal PRD §10 fields — change summary, changed files, validation status, conflict status, target branch — plus approval state; the three decisions are offered only while awaiting review, only for a resolved session identity, and a decided request renders its recorded state with immutable-decision copy (the buttons never return). Git-aware run cards join the runtime's project ledger on real task ids (project, branch, worktree state, validation status) — a run without git work renders no git line at all. The browser allowlist grew by exactly the S19 reads (`/v1/projects`, project detail, worktrees, merge-requests) and the two mutations (one decision, one validation run); there is deliberately NO browser path for project import/clone, credential store/revoke, or worktree allocation.

## Alternatives considered (preserved)

- **A zip/tar library dependency for archive import:** rejected — the module's auditability IS the point of a sensitive slice; the hand-rolled reader keeps the refused surface typed and the guards enumerable. `node:zlib` primitives only.
- **Credential custody via a git credential helper:** rejected — a helper outside the vault would be an invisible, unauditable credential path; the runtime clears ambient helpers per invocation (`-c credential.helper=`) and injects at call time instead.
- **URL-embedded userinfo as the credential carrier for imports:** refused outright — the embedded form would land in `.git/config` in plaintext; the credential is sealed into project custody and re-injected at call time.
- **`resource_scope` carrying the project UUID:** rejected for the approval card's readability — the approval boundary's entropy-redaction pass would render a UUID as `[REDACTED]`; the sanitized project name is the human-readable repository identity, with the durable linkage on the merge-request row and the exact change set pinned by `args_digest`.
- **A parallel merge-decision route bypassing S20:** rejected — the whole point is that repository mutation rides the SAME D9 machinery; the projects surface owns zero approval rules.
- **Widening the conflict queue to path-level leases in this slice:** deferred — the per-project-exclusive partial index is enforceable at the storage layer today; widening is an integration decision, not silently absent.
- **`gunzipSync` for tar.gz:** superseded by the security review — an unbounded inflate before any cap was a decompression-bomb vector; `gunzipCapped` bounds the stream.
